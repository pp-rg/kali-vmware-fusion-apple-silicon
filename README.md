# kali-vmware-fusion-apple-silicon

Make a **Kali Linux ARM64 VM in VMware Fusion on an Apple Silicon Mac** feel like macOS:
Mac keyboard bindings that work in every app, a sharp Retina display, and a responsive desktop.

Tested on: MacBook M1, Fusion 13, Kali rolling (kernel 7.1, Xfce 4.20, X11), Apple ISO French keyboard.
Not tested: Intel Macs, Wayland, other desktops. Other layouts are generated from the XKB data and dry-run checked, not typed on real hardware.

## 1. Fusion settings (before installing)

| VM Settings | Value |
| --- | --- |
| Keyboard & Mouse > Key Mappings | **off** (otherwise Fusion rewrites Cmd+C into Ctrl+C) |
| Mac host shortcuts | **off** |
| Display > Use full resolution for Retina display | **on**, then use full screen |
| Display > Accelerate 3D graphics | on |
| Isolation > Enable copy and paste | on |
| Processors & Memory | 4 cores, **4 GB RAM** on an 8 GB Mac (less than ~3 GB makes the VM swap, more makes macOS swap) |

Take a snapshot first.

## 2. Install

```bash
git clone https://github.com/pp-rg/kali-vmware-fusion-apple-silicon.git && cd kali-vmware-fusion-apple-silicon
./install.sh --layout fr        # fr, us, gb, de, it, se, ... ; default = the layout in use
```

Log out and back in, then go full screen. `./uninstall.sh` reverts everything (`*.bak-<date>` backups are kept).

| Option | Effect |
| --- | --- |
| `--layout CODE` `--variant NAME` | keyboard layout (`./keyboard/install.sh --list-layouts` lists those with a Mac variant) |
| `--keep-layout` | keep the system layout, only add the Mac bindings |
| `--swap-iso` | swap the `grave`/`102nd` keys (some Apple ISO keyboards send `@#` and `<>` crossed: press `@#` under `sudo keyd monitor`; if it prints `102nd`, you need it) |
| `--root` | also install the shell bindings for root |
| `--no-keyboard` `--no-display` `--no-perf` | skip a module |

## 3. Bindings

Everywhere:

| Shortcut | Action |
| --- | --- |
| Cmd + letter | Ctrl + letter (C V X Z A S F T W Q N ...) |
| Cmd + `1` ... `9` (the digit-row keys, e.g. `&` `é` `"` on AZERTY) | tab 1 ... 9 (browsers, file managers, editors, terminals) |
| Option + Left/Right, Option + Backspace/Delete | previous/next word, delete word |
| Cmd + Left/Right, Cmd + Up/Down, Cmd + Backspace | line start/end, document start/end, delete to line start |
| Cmd + Tab, Cmd + Shift + Tab | next/previous window (hold Cmd, press Tab repeatedly) |
| Option | AltGr: all Mac characters |

In terminals (QTerminal, Xfce Terminal, GNOME Terminal, kitty, alacritty): Cmd + C/V copy/paste, Cmd + T/N new tab, Cmd + W close tab, Cmd + F find, Cmd + K clear, Cmd + `=` / `-` / `0` zoom in / out / reset, Shift + Enter newline without running (zsh, bash, tmux). Ctrl-based shortcuts are unchanged.

Key positions depend on the layout (the key labelled W is `z` for keyd on AZERTY): `keyboard/gen-app-conf.py` resolves them from the real XKB layout, so the same rules work on AZERTY, QWERTY, QWERTZ, ...

## 4. Display and performance

- **Display:** automatic 1x/2x scaling when the guest is 2560 px wide or more (GTK, cursor, window theme, Qt), square window corners.
- **Performance:** zram (compressed swap in RAM), snappier window switcher, a patched `keyd-application-mapper` (no CPU burn in a terminal), a panel that slides in/out in ~0.15 s instead of 1.8 s, useless autostarts disabled.

## 5. Known limits

- macOS may keep Cmd+Tab / Cmd+Space for itself.
- Cmd + digit sends Alt + digit to every application. In an app where Alt + digit means something else, edit the `[*]` section of `~/.config/keyd/app.conf` (regenerated by the installer).
- Switching to a terminal tab that redraws the whole screen continuously (a TUI) is slower (~0.6 s measured) than to a normal one (~0.15 s): software rendering at 2880x1800.
- Installers are syntax-checked and each step was applied on the original VM, but a full `install.sh` was not replayed on a fresh VM. Use a snapshot.
